Farm management system — build checkpoint

Farmloop, documented so far

Permissions

apps/core/permissions.py — IsFarmMember (any authenticated user with a farm), IsFarmAdmin (role must be ADMIN; gates team/audit/analytics/schedule editing), and require_plan_tier(*tiers), a factory gating a view to specific subscription tiers independent of role.

Background jobs — Celery Beat

Management commands

  • manage.py seed_demo — seeds a realistic demo farm, idempotent (owner + farmhand, 1 farm, 3 zones, 3 inventory items, 2 supplies, 3 recurring schedules with generated occurrences, 2 audit entries).
  • manage.py demo_token [email] — prints a fresh JWT access token for Swagger's Authorize button. Omit the email for both demo users at once.

State management notes

  • AsyncValue.valueOrNull doesn't exist in Riverpod 3.x — use .value directly (nullable in this version).
  • An action-only controller read solely via .notifier (never .watch'd) has nothing keeping it alive under default autoDispose, and can be disposed mid-mutation, silently dropping the ref.invalidate() that should refresh the UI. Every action controller here (TeamActionsController, SupplyActionsController, …) is marked @Riverpod(keepAlive: true) for exactly this reason.

Dev workflow quirks

  • Web preview: flutter run -d web-server hangs in this sandbox (no Dart Debug Chrome Extension). Use flutter build web --debug -o build/web then serve with a static file server — wired into .claude/launch.json.
  • iOS Simulator: tap coordinates are in device points, not screenshot pixels (iPhone 17 Pro: 402×874pt, screenshot-px→pt scale ≈2.3). There's real latency between a tap and the screenshot reflecting it — a screenshot alone isn't proof an action registered; mutating actions were re-verified directly against the backend.
03

Running it locally

Backend needs PostgreSQL and Redis running locally.

Backend

cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # fill in DATABASE_URL at minimum
python manage.py migrate
python manage.py seed_demo
python manage.py runserver 0.0.0.0:8000

Background jobs: celery -A config worker -l info and celery -A config beat -l info.

Mobile — web preview

cd mobile
flutter build web --debug -o build/web
cd build/web && python3 -m http.server 5050

Mobile — iOS Simulator

cd mobile
flutter build ios --debug --simulator

Install the built .app onto a booted simulator.

Status & open items

Invite dialog (Team screen) — not verified via simulator automation. The FAB tap didn't register across 7 calibrated attempts, while every other tap on the same screen worked with the same calibration. Code review shows a standard showDialog, consistent with the rest of the app — reads as an automation-tool limitation, not an app bug, matching an earlier confirmed case with the Triage swipe gesture. Needs a manual tap to confirm.
  • farm/ and notifications/ mobile features are scaffolded folders only — no screens built yet.
  • No automated integration/E2E suite beyond flutter analyze / flutter test (unit-level) and manual backend-query verification during simulator testing.
  • The project is not yet under git version control.
